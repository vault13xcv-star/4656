# Физическое ТЗ: состояние рабочей версии 0.5.2-preview.1

Основа: стабильная ветка `experimental/ragdoll-0.4.1-windows`, коммит
`4bda0b6912fa24540e5701dd4f7e296e19502d54`. По указанию пользователя локальная
непроверенная версия исключена из задачи. Переписывание проекта с нуля не нужно.

Это промежуточная тестовая реализация. Полное ТЗ не объявляется выполненным.
Подробная установка и настройки — в [основном документе](realcombat-ragdoll.md).

## Изменения требований по последней просьбе пользователя

Теперь покрытия включают волосы, одежду, броню и щит; прежнее требование ТЗ
сохранять их материалы отменено пользователем. При выгрузке локации больше не
сохраняются позы и покрытия трупов: остаётся только обычное положение ссылки,
а на возвращении используется штатная конечная поза смерти. Это сознательное
изменение требования постоянного хранения RPHY между выгрузками. В активной
ячейке сохранение/загрузка RPHY продолжает работать.

Исправлен преждевременный выбор цели снаряда внутри callback Bullet; фиксация
теперь происходит после завершения sweep. Ближний бой повторно проверяет
предметы в момент удара и использует небольшой участок вместо единственного луча.
Добавлены проверки порядка коллизий «стена/бутылка», преград, общих Drawables,
90% покрытия гарью, 70–80% непрозрачности инея и освобождения поз при выгрузке.

## Дополнения 0.5.2 по новой просьбе

Добавлена нативная вкладка «Физика» с 11 ползунками 50–200% и сбросом. Теперь
допускаются до 200 активных тел и отдельно 200 вещей при стандартных 100+100.
Это заменяет прежний жёсткий предел 100 из ТЗ. Метательное оружие получает
небольшую настраиваемую базу импульса, заменяя прежнее требование нулевого
добавочного отброса. Базы арбалета, лука, древкового оружия и поиск опоры
пригвождения немного увеличены. Ползунки не меняют игровые повреждения.

Исправлен оставшийся геометрический дефект ближнего боя: модельный порядок
поворотов разворачивал вертикальную составляющую при изменении азимута.
Добавлены настоящие нативные попадания вниз при пяти направлениях для всех
12 классов подбираемых вещей, проверка камеры первого лица, меню и локализации,
лимитов 200 и изменения таймеров без их повторного запуска. Игровая проверка
конкретных NIF/анимаций по-прежнему требуется.

## Реализованные изменения

| Область | Состояние кода и проверок |
| --- | --- |
| Предметы: таймер, покой, пробуждение | Собственные окна до 10 с, повторный удар не продлевает окно. Покой — фиксированная коллизионная форма. Контакты и новые удары снова запускают физику. Проверено на Bullet. |
| Два бюджета | Независимые стандартные пределы 100+100, меню позволяет 50–200 каждого. Вытеснение старых сущностей, сохранение конечной позы и лута. Проверены переполнение, расстояние и повторная активация. |
| Контакт персонаж–предмет | Проверка формы/движения персонажа, передача нормального и касательного импульса; телепорты отфильтрованы. Есть тест реального Bullet. Требуется игровой прогон. |
| Сохранение предметов | В активной ячейке `IPHY` сохраняет оставшееся время и скорости. При подборе и выгрузке ячейки сбрасывается; штатные позиция/поворот остаются. Есть нативные ESM-тесты и тест восстановления решателя. |
| Сохранение трупов | В активной ячейке `RPHY` сохраняет тела/суставы/позы, скорости, режим, возраст эффекта, крепление и притяжение. При выгрузке ячейки освобождается; остаётся обычное положение ссылки. Проверены ESM round trip, синтетический скелет и сброс при выгрузке. |
| Гуманоид | 15 физических частей, включая кисти/стопы. Начальная скорость и обновление массы брони. Анатомические регрессии и поза после восстановления проверяются Bullet/OSG. |
| Вес оружия и сила | Границы веса рассчитываются при подготовке контента; усилители складываются до ×3, Strength насыщается на 100. Стрелы/болты и магия отдельно. Формулы проверены. |
| Место попадания | Нативный контакт выбирает ближайший сегмент и мировой рычаг импульса. Колющий/боковой удар всё ещё использует запасное определение направления по типу атаки. |
| Крепление | Sweep формы поражённого сегмента, приближение к статической поверхности без телепортации, сохранение подвешенной позы. Видимый болт и удаление опоры ещё не завершены. |
| Магия | Один победитель по эффективному урону задаёт статус и импульс. R=0, край/выход за радиус и эффекты здоровья не дают выдуманного отброса. Проверены формулы и порядок эффектов. |
| Яд | Направленное внутрь ограниченное притяжение с демпфированием, масса и коллизии. Нет собственного импульса предметам. Проверены примеры R=10, d=3/9,9, тяжёлая цель и тонкая стена. |
| Посмертные эффекты | Огонь/дым 15 с, ядовитый дым и электрические разряды 10 с. Собственные таймеры, экземплярные покрытия. GL-тесты подтверждают видимость, перекрытие стеной и завершение при двух режимах глубины. |
| Существа | Профили массы/исключений по ID/модели, стандартный гуманоид либо приближённая иерархия костей. Проверены классификатор и синтетический негуманоид с холодом/сохранением. Покрытие всех игровых скелетов НЕ подтверждено. |
| Вода | Силы плавучести и сопротивления, тяжёлые трупы и холод. После 10 с разрешено только продолжение всплытия одним жёстким телом в том же бюджете. Физический тест есть; игровой прогон отсутствует. |
| Производительность | Активные предметы и изменения состояния выделены отдельно, без обхода всей неподвижной расстановки в цикле обновления. Есть воспроизводимый синтетический benchmark 0/10/50/100 и 100+100. Это не игровой FPS. |

## Ограничения и следующий этап

Пока не реализован полноценный общий обмен импульсами между трупами,
персонажами и предметами. Каждый труп по-прежнему имеет отдельный динамический
мир; предметы — свой. Для следующего этапа нужен общий сервис либо корректный
двусторонний мост контактов с идентичностью объектов и ограничениями потоков.

Профили существ в `components/ragdoll/profiles.hpp` задают начальные массы и
размеры. Универсальная модель не заменяет индивидуальные суставы для каждого
штатного скелета. Локализованные отображаемые имена не используются.

Новые физические данные являются расширением сохранений изменённого движка.
Обратная совместимость новых сохранений со стабильной 0.4.1/обычным OpenMW
не гарантируется. Исходные сохранения нужно сохранять отдельно.

Windows-пакет считается построенным только после успешного CI: весь движок,
компонентные тесты, нативная интеграция предметов, установленный `--version`,
DLL и ZIP. Успешные математические или GL-тесты сами по себе этого не доказывают.
Без игровых ресурсов в облаке полноценная игровая приёмка не проводилась.
